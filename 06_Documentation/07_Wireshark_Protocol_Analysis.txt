# 07. Wireshark Protocol Analysis

## 1. Introduction

Wireshark is a network protocol analyzer used to capture and inspect packets exchanged over a network.

In this project, Wireshark was used to analyze ICMP, TCP, DNS, HTTP, and HTTPS traffic generated by the host computer.

**Capture environment:** Host laptop Wi-Fi interface.

**Important:** These captures were collected from the actual host network, not directly from the Cisco Packet Tracer simulated network. They provide supplementary hands-on protocol analysis.

## 2. ICMP Analysis

**Capture file:** `01_ICMP_Analysis.pcapng`

**Evidence screenshot:** `01_ICMP_Analysis.png`

ICMP traffic was generated by pinging the public IP address 8.8.8.8.

The capture contained:
- ICMP Echo Request packets.
- ICMP Echo Reply packets.
- Source IP address: 192.168.31.30.
- Destination IP address: 8.8.8.8.
- Observed request TTL: 128.
- Observed reply TTL: 111.

This analysis demonstrated how ICMP is used for network reachability testing.

## 3. TCP Analysis

**Capture file:** `02_TCP_Analysis.pcapng`

**Evidence screenshot:** `02_TCP_Analysis.png`

TCP traffic was captured while accessing a website through a browser.

The capture demonstrated TCP communication between the host computer and remote servers.

TCP provides:
- Connection-oriented communication.
- Reliable data delivery.
- Sequence and acknowledgement mechanisms.
- Retransmission when required.

## 4. DNS Analysis

**Capture file:** `03_DNS_Analysis.pcapng`

**Evidence screenshot:** `03_DNS_Analysis.png`

DNS traffic was generated using hostname lookup commands for domains including:
- google.com
- youtube.com
- amazon.com

The captured packets demonstrated DNS queries and corresponding responses.

DNS translates human-readable domain names into IP addresses, allowing applications to locate network services.

## 5. HTTP and HTTPS Analysis

**Capture file:** `04_HTTP_HTTPS_Analysis.pcapng`

**Evidence screenshots:**
- `04_HTTP_Analysis.png`
- `05_HTTPS_Analysis.png`

HTTP traffic was generated by accessing `http://neverssl.com`.

HTTPS traffic was generated by accessing `https://example.com`.

The capture showed:
- An HTTP GET request for `/favicon.ico`.
- An HTTP/1.1 200 OK response.
- TLS 1.3 Application Data packets.

HTTP transmits application data without transport-layer encryption by itself. HTTPS uses TLS to protect communication between the client and server.

## 6. Protocol Summary

| Protocol| Purpose                  | Observation              |
|---------|--------------------------|--------------------------|
| ICMP    | Network diagnostics      | Echo request and reply   |
| TCP     | Reliable transport       | TCP communication        |
| DNS     | Name resolution          | Queries and responses    |
| HTTP    | Web communication        | GET request and 200 OK   |
| HTTPS   | Secure web communication | TLS 1.3 application data |

- Inspecting TCP traffic.

- Recognizing TLS-encrypted application data.

Wireshark analysis complemented the Cisco Packet Tracer enterprise network project by providing practical exposure to real host-network traffic.
